# Cover letter strategy

A cover letter argues one point: this candidate has already done a version of the job in the
posting. Everything in it comes from the posting on one side and the master resume on the other.

## Mine the posting first

Before writing, pull out:

1. **The main problem.** The duty listed first or repeated most. The opening answers it.
2. **The top three duties.** The second paragraph maps evidence to these, in the posting's order.
3. **The preferred qualification the user holds** that most applicants at this level lack. This is
   the differentiator.
4. **The posting's own phrases.** Echo three to five of them where they fit a true sentence.
5. **Instructions.** A named contact, a reference number, questions to answer, salary expectations
   to state. Posting instructions override the default structure.
6. **One true fact about the employer** that connects to the user's work or goals: a product, a
   client group, a market, a stated value, a recent event. Search the web when a search tool is
   available, or ask the user. Never invent a fact about the employer.

## Structure

Four paragraphs, 250 to 400 words, one page in the shipped template.

1. **Role and hook.** State the role title, the reference number when the posting gives one, and
   the availability from `profile.md`. Then the single strongest overlap between the user's work
   and the main problem. Start with the application itself. No warm-up sentence.
2. **Evidence.** Two or three pieces of work mapped to the top duties. Each one says what the user
   did, at what scale, and what came of it. Add what the resume has no room for (why a decision was
   made, what went wrong, what the user learned) only when the master or the user supplies it. Do
   not copy resume bullets.
3. **Differentiator.** What this candidate brings that the other applicants probably do not: a
   second field, a language, production responsibility, a client-facing record. Address a missing
   required qualification here when the gap is obvious, in one honest sentence about how the user
   is closing it.
4. **Close.** The one true fact about the employer and why it matters to the user. Thanks. No
   claims about being the best candidate.

**Salutation**: the person the posting names, otherwise "Dear <Company> Hiring Team,". The
salutation ends with a comma.

**Date**: written out, such as "September 7, 2026".

**Sign-off**: "Sincerely," and the sign-off name from `profile.md`.

## Strategy by posting type

| Posting signal | Letter emphasis |
|---|---|
| Long list of technical requirements | Paragraph 2 names the systems built with those tools and their scale. |
| "Fast learner", "strong fundamentals", no fixed stack | Show one case of learning something by shipping it. |
| Client or stakeholder contact | A specific client interaction and its result. |
| Regulated or high-accuracy work (finance, health, legal) | Controls, checks, and what the user did when something was wrong. |
| Leadership or ownership language | Something the user ran end to end, with the number of people or the budget. |
| Mission-driven employer | A concrete personal link to the mission, stated once, with no adjectives. |
| Career change | Lead with the transferable result, then say plainly why the change. |

## Field notes

- **Investment banking and finance.** Three questions decide the letter: why this firm, why this
  group, why the candidate. Ask the user who at the firm they have spoken to and what they learned.
  Name those people in the opening when the user agrees. A deal the firm advised on may be cited
  only after confirming it from a source. Keep the letter at the short end of the range.
- **Consulting.** Leadership and measurable impact lead. Name the office and say why.
- **Tech.** Describe the system the user built that most resembles the team's product. A link to
  the running work is worth a sentence.
- **Other fields.** Use the field's proof from `references/fields.md` as the evidence.

## When there is no cover letter

Skip the letter when the employer's form has no place for one or the posting says not to send one.
Tell the user it was skipped and why. When the form asks short written questions instead ("Why
this company?"), offer to draft those answers with the same rules.

## Style

All rules in `references/writing.md` apply. The cover letter template contains no bold labels, so
no colon appears anywhere in a letter.
